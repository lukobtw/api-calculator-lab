# API Calculator

Учебный REST API-калькулятор на Python и FastAPI с контейнеризацией
и автоматическими проверками безопасности в GitHub Actions.

Работа была выполнена совместно студентами Яцким Максимом Евгеньевичем и Ковшевниковым Павлов Сергеевичем, РИ-431003

## Возможности

- Сложение, вычитание, умножение и деление.
- Проверка входных данных.
- Обработка деления на ноль.
- Интерактивная документация Swagger UI.
- Автоматическое тестирование и сборка Docker-образа.
- Проверка кода и компонентов контейнера с помощью Semgrep и Trivy.

## Технологии

- Python 3.11
- FastAPI
- Uvicorn
- Pytest
- Docker
- GitHub Actions
- Semgrep
- Trivy

Версия API в приложении: `1.0.0`.

## Запуск в Docker

Необходимы установленные Git и Docker.

### 1. Клонирование репозитория

```bash
git clone https://github.com/lukobtw/api-calculator-lab.git
cd api-calculator-lab
```

### 2. Сборка образа

```bash
docker build --pull -t calculator-api:local .
```

### 3. Запуск контейнера

```bash
docker run -d --name calculator-api -p 127.0.0.1:8000:8000 calculator-api:local
```

После запуска доступны:

- API: http://localhost:8000
- Swagger UI: http://localhost:8000/docs
- ReDoc: http://localhost:8000/redoc

### 4. Проверка работоспособности

```bash
curl http://localhost:8000/
```

В Windows PowerShell вместо `curl` можно использовать `curl.exe`.

Ожидаемый ответ:

```json
{
  "message": "API Calculator is running"
}
```

### Управление контейнером

Просмотр журналов:

```bash
docker logs calculator-api
```

Остановка:

```bash
docker stop calculator-api
```

Удаление остановленного контейнера:

```bash
docker rm calculator-api
```

## API

| Метод | Адрес | Назначение |
|---|---|---|
| GET | `/` | Проверка работоспособности приложения |
| POST | `/calculate` | Выполнение арифметической операции |
| GET | `/docs` | Swagger UI |
| GET | `/redoc` | ReDoc |

### Параметры вычисления

| Поле | Тип | Описание |
|---|---|---|
| `operation` | string | Операция: `add`, `subtract`, `multiply`, `divide` |
| `a` | number | Первый аргумент |
| `b` | number | Второй аргумент |

### Пример запроса

Открой http://localhost:8000/docs, выбери `POST /calculate`,
нажми **Try it out** и передай:

```json
{
  "operation": "multiply",
  "a": 6,
  "b": 7
}
```

Ожидаемый ответ с HTTP 200:

```json
{
  "operation": "multiply",
  "a": 6.0,
  "b": 7.0,
  "result": 42.0
}
```

### Обработка ошибок

| Ситуация | HTTP-код |
|---|---|
| Деление на ноль | 400 |
| Неизвестная операция | 422 |
| Отсутствие обязательного поля или некорректный тип аргумента | 422 |

При делении на ноль возвращается:

```json
{
  "detail": "Division by zero is not allowed"
}
```

## Локальный запуск без Docker

Необходим Python 3.11.

Создание виртуального окружения:

```bash
python -m venv .venv
```

Активация в Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

Активация в Linux:

```bash
source .venv/bin/activate
```

Установка зависимостей и запуск:

```bash
python -m pip install -r requirements-dev.txt
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

## Автоматические проверки в GitHub Actions

Workflow запускается при:

- push в ветку `main`;
- создании или обновлении pull request в ветку `main`.

Сначала выполняются тесты. После их успешного завершения
запускаются сборка образа и проверки безопасности.

| Задание | Действия |
|---|---|
| `test` | Установка зависимостей и запуск Pytest |
| `docker-build` | Сборка образа с тегом, соответствующим хешу коммита |
| `semgrep` | Статический анализ исходного кода и конфигурации |
| `trivy` | Проверка файлов репозитория, отдельная сборка и проверка Docker-образа |

Результаты запусков доступны во вкладке
[Actions](https://github.com/lukobtw/api-calculator-lab/actions).

При каждом таком запуске создаётся новая сборка образа.
Публикация образа в registry, автоматическое развёртывание
и изменение версии API пока не настроены.

## Проверки безопасности

### Semgrep

Проверяет исходный код и конфигурационные файлы
с использованием автоматически выбранного набора правил.

Результат сохраняется в артефакт `semgrep-report`:

- `semgrep-report.json`.

### Trivy

Проверяет зависимости репозитория и компоненты Docker-образа.
В отчёт включаются находки уровней `HIGH` и `CRITICAL`.

Результаты сохраняются в артефакт `trivy-reports`:

- `trivy-fs-report.json`;
- `trivy-image-report.json`.

Для скачивания отчётов открой нужный запуск GitHub Actions
и перейди к разделу **Artifacts**.

### Текущая политика проверок

Проверки безопасности работают в режиме формирования отчётов:

- у Semgrep установлен `continue-on-error: true`;
- команда Semgrep не содержит `--error`;
- у Trivy установлен `exit-code: "0"`.

Поэтому успешный статус CI не гарантирует отсутствия уязвимостей.
